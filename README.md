# quietkey

一个热键暂停/播放后台的视频，**不切窗口、不抢焦点、不打断打字**。

写笔记的时候想暂停视频，不用再 Alt+Tab 过去按空格再切回来。

Windows 专用，C++17 + Win32 + C++/WinRT，无第三方依赖，单文件约 500 KB。

## 它和「切窗口按空格」的脚本有什么不同

常见做法是：激活视频窗口 → 模拟按空格 → 再激活回笔记窗口。能用，但有两个硬伤：
屏幕会闪，而且焦点被抢走的那一瞬间打的字会散落到别的窗口里。

quietkey 走的是四层策略链，逐层降级，**前三层完全不碰前台焦点**：

| 层 | 手段 | 适用 | 打扰 |
|---|---|---|---|
| 1 | Windows 媒体会话（GSMTC） | 浏览器网页视频、Spotify 等 | 无 |
| 2 | `WM_APPCOMMAND` 定向投递 | VLC / PotPlayer / foobar2000 | 无 |
| 3 | `PostMessage` 键盘消息 | 原生 Win32 播放器 | 无 |
| 4 | 抢焦点 + `SendInput` + 还原 | 兜底，默认关闭 | 屏幕闪一下 |

第一个成功的层即生效。界面上会显示这次命中的是哪一层，一眼看出有没有掉到会闪烁的兜底路径。

### 为什么网页视频必须走第 1 层

向浏览器的顶层窗口投递合成的 `WM_KEYDOWN` 是**行不通的**——Chromium 的键盘输入
走自己的 renderer 输入管线，不读顶层窗口的消息队列，合成消息会被直接丢弃。

所以对网页视频来说，媒体会话 API 不是优化，而是唯一可行的无感方案。好处还不止于此：
它不依赖窗口标题（标题会随播放进度变），窗口最小化或被完全遮挡也照样生效。

### 同时开着多个视频时，控哪一个

跟随**你最近手动播放或暂停过的那一个**。

判据是每个媒体会话自带的「播放位置信息最后更新时刻」——手动播放、暂停、拖进度条
都会刷新它，而一直播着不动**不会**。所以"播了又停"这种净状态没变的操作也认得出来。
按会话逐个比时间戳，与具体是哪个播放器无关，同一浏览器的不同视频标签页也能分开。

在「策略链 → 跟随最近播放/暂停过的那个视频」可以关掉这个行为。
「目标窗口」里填了进程名的话，仍以配置为准。

### 为什么用 RegisterHotKey 而不是键盘钩子

- **杀软**：全局低级键盘钩子是 keylogger 的教科书特征，未签名的自编译程序很容易被拦。
- **全系统输入延迟**：钩子回调跑在本进程，受 `LowLevelHooksTimeout`（约 300ms）约束，
  在回调里做窗口查找会拖慢**整个系统**的键盘响应。
- **隐私**：钩子能看到你敲的每一个字符，`RegisterHotKey` 只能看到注册的那一个组合键。

附带好处：系统会独占消费注册过的组合键，不会再漏给正在打字的笔记软件。
空闲时进程完全休眠，CPU 占用 0%。

## 使用

双击 `build\quietkey.exe` 即可，无依赖、单文件。首次启动会自动弹出设置界面：

1. **全局热键** —— 点进热键框直接按组合键（默认 `Alt+Q`）。
   > 系统的热键控件不支持 Win 键。需要 `Win+X` 这种组合的话，
   > 直接改配置文件里的 `hotkey=Win+X`，程序能解析。
2. **目标窗口** —— **只有第 2/3/4 层需要它**。点「从窗口列表选择…」在列表里双击你的播放器。
   存的是进程名 + 窗口类名这类匹配规则，不是窗口句柄，所以播放器重启后依然有效。
   标题默认不参与匹配（它会随播放进度变）。
   > 控制浏览器网页视频的话第 1 层就够了，这一步可以跳过。
3. **保存并应用**，然后关窗口——程序缩到托盘继续跑。

托盘图标双击可以再打开设置，右键菜单里有「立即播放/暂停」和「退出」。
**关窗口不会退出程序**，真正退出只走托盘菜单的「退出」。

配置存在 `%APPDATA%\quietkey\config.ini`（UTF-16，记事本可直接编辑）。
想恢复出厂设置就删掉它。

## 排查

界面下方的「诊断」区：

- **立即测试一次** —— 用界面上当前的设置试一次，不必先保存。「上次触发」会列出
  每一层的尝试结果和耗时。
- **刷新媒体会话** —— 列出系统当前所有媒体会话，`★` 标出「最近碰过」的那一个
  （也就是热键会作用的目标）。**如果你的播放器不在这个列表里，说明它没注册媒体会话，
  第 1 层对它无效**，得靠第 2/3 层（需要填目标窗口）。

### 按了热键没反应？按这个顺序查

1. **托盘图标还在吗** —— 程序退了的话，热键当然没人接。
2. **`--list-sessions` 里有没有你的播放器** —— 浏览器会在标签页被丢弃、视频静音、
   长时间暂停之后**撤销媒体会话**。这时候即使页面还开着、看起来在播，
   系统里也是空的。**在播放页面按一下 F5 重新播放**，通常立刻就恢复了。
3. **有会话但控不到** —— 看「上次触发」里的逐层 trace，命中路线会写明白。

命令行也能跑诊断，不用开界面：

```powershell
quietkey.exe --list-sessions   # 只读列出媒体会话，不会动你的视频
quietkey.exe --test-once       # 按当前配置跑一次策略链并打印逐层结果
quietkey.exe --console         # 正常启动，但把运行日志打到当前终端
```

`--list-sessions` 输出示例：

```
共 2 个媒体会话：
  ▶ 播放中    msedge                   301.8 秒前碰过
  ⏸ 已暂停 ★ chrome                   最近碰过
```

`--test-once` 输出示例：

```
结果: PostMessage 按键 · 空格已投递到 notepad.exe 的窗口（无法确认是否响应） · 2.4ms
  目标窗口             命中  notepad.exe · 「无标题 - 记事本」
  WM_APPCOMMAND      跳过  notepad.exe 未处理 WM_APPCOMMAND
  PostMessage 按键     命中  空格已投递到 notepad.exe 的窗口（无法确认是否响应）
```

程序不带控制台，上面这些输出靠挂到你启动它的那个终端。重定向到文件也可以：

```powershell
quietkey.exe --list-sessions > sessions.txt
```

日志还会同时写 `OutputDebugString`，用 DebugView 之类的工具能随时旁观，不必重新编译。

# 自己编译

## 环境

- **Visual Studio 生成工具 2022**，安装时勾选「使用 C++ 的桌面开发」
  （自带 MSVC、Windows SDK、CMake、Ninja，不用另外装）

其它什么都不需要——没有第三方库，没有包管理器。

## 命令

```powershell
build.bat          # Release 构建 → build\quietkey.exe
build.bat debug    # Debug 构建
build.bat clean    # 删掉 build 目录
```

`build.bat` 会自己找到 Visual Studio、进 x64 编译环境、调用 CMake + Ninja，
**不需要你手动 vcvars，也不需要 cmake 在 PATH 里**。

> 编译报 `拒绝访问`，是因为目标 exe 正在运行，先从托盘退出它再编。

## 项目结构

```
quietkey/
├── CMakeLists.txt         工程定义（C++17、/utf-8、/W4）
├── build.bat              一键构建（纯 ASCII，见 CLAUDE.md 里的原因）
├── README.md              本文件
├── CLAUDE.md              设计依据与踩过的坑，改代码前该看的文件
├── tools/
│   └── make_icon.cpp      构建期程序化生成多尺寸 .ico，不在仓库放二进制资源
└── src/
    ├── main.cpp           入口、隐藏窗口、消息循环、单实例、命令行诊断
    ├── app.rc             图标、manifest、版本信息、两个对话框模板
    ├── app.manifest       视觉样式 + PerMonitorV2 + asInvoker
    ├── resource.h         资源与控件 ID
    ├── settings.h/.cpp    设置对话框 + 窗口拾取器
    ├── config.h/.cpp      INI 读写
    ├── hotkey.h/.cpp      热键注册 + "Alt+Q" 字符串解析
    ├── tray.h/.cpp        托盘图标与右键菜单
    ├── log.h/.cpp         日志与控制台挂载
    ├── winutil.h/.cpp     窗口枚举、目标解析、抢前台、SendInput
    ├── strategy.h/.cpp    策略链调度器
    ├── gsmtc.cpp          第 1 层：媒体会话（C++/WinRT）
    ├── recency.h/.cpp     「最近被播放/暂停过的是哪个会话」
    ├── messages.cpp       第 2 层 WM_APPCOMMAND + 第 3 层 PostMessage
    └── fallback.cpp       第 4 层 抢焦点 + SendInput
```
